00

What is already shipped

Said first because it reframes everything below: the original roadmap has, in effect, been built. Almost every idea it listed is now a working feature. This document is therefore a fresh roadmap for the remaining work, not a re-statement of the old one.

Reactor & visuals

  • Software 3D tokamak with a raymarched WebGL volumetric plasma core that falls back safely to software
  • On-screen fusion events: core flashes, alpha particles, neutrons fired to the blanket
  • Multi-pass bloom, living-plasma turbulence, atmospheric fog, vignette
  • Cutaway cross-section, human/scale reference, neutron wall-heat map
  • Visible disruption event (shake + flash), divertor strike-point sweep

Teaching, UI & robustness

  • Guided story, guided tour, seven missions, predict-then-test, contextual coach
  • Four themes (control-room, light, high-contrast, colorblind), reduced-motion path
  • Real-world units, model-assumptions card, glossary, Balance-of-Plant flow
  • Kiosk/Present mode, idle watchdog, tab-hide pause, lite-GPU path, WebGL context-loss recovery
  • CSV export, QR takeaway card, web-app manifest + icon, student worksheet + instructor key

What that leaves on the old roadmap

Only the three "ambitious" bets remain genuinely unbuilt: a full Three.js render track (the raw-WebGL plasma already captures much of its payoff), a two-player race-to-ignition, and a WebXR booth mode. They are carried forward into Section 06 as optional ceiling-raisers.

03

Donation blockers — a reviewer's first gate

These three are cheap and decisive. They are what an institutional legal/accessibility/curriculum check catches within minutes, regardless of how good the rest is.

Do these before anything else

A program's adoption decision can fail on any one of these in isolation. None is a large build; together they are an afternoon.

Add a LICENSE file

T0·1

The About panel and the takeaway card both promise "Donated for educational use, free to run and share," but with no license the default is all-rights-reserved — so the promise is technically false and a careful program cannot legally adopt, modify, or rebrand it.

Why it matters: undefined reuse terms are a routine auto-reject for institutional software. This is the single biggest legal blocker.

Hook: MIT or Apache-2.0 for the code, CC BY 4.0 for the worksheet/key/assets; name the copyright holder; add a README "License" section. The in-app copy at index.html (About) and script.js (takeaway card) becomes true the moment the file exists.
BlockerEffort · LowAll

Add a global keyboard focus ring

T0·2

Only button.plant-stage has a real :focus-visible style; ~40 controls fall back to a near-invisible default on the dark glass, and .tip-dot:focus-visible sets outline:none with no substitute.

Why it matters: an invisible focus indicator is the most common WCAG 2.4.7 failure and is disqualifying on most campus accessibility checklists — a disability office runs a keyboard-only pass first.

Hook: one token rule, e.g. :where(button,[role=button],input,select,summary,.hotspot,.tool-btn,.nav-btn,.gizmo-btn,.preset,.predict-choice):focus-visible{outline:2px solid var(--teal);outline-offset:2px;box-shadow:0 0 0 4px rgba(56,225,198,.25)} plus a range-thumb ring; restore an outline on .tip-dot.
BlockerEffort · LowAll

Fix the learning-flow truth slips

T0·3

Three small contradictions that the most scrutinizing readers — teachers — catch:

  • Instructor key Cruise Q says "Q of a few"; the model settles at Q ≈ 20 (verified live, ~+311 MW). Off by ~5×.
  • README says the tour "runs on first visit," but fusionTourDone is written and never read, and startTour() only fires from the button.
  • Guided story step 1 ("too cold to fuse, watch the core stay dark") opens over a glowing 11 keV reactor because the story never applies a cold baseline.

Why it matters: the answer key and the guided flow are exactly what an educator trusts the exhibit on. A value off by 5× or a step that contradicts the screen makes them doubt the whole tool.

Hook: correct the key to a model-matched range; either wire the first-run flag or fix the doc line; apply a cold preset when the story opens (and reuse the tour spotlight for U4).
BlockerEffort · LowUG / educators
04

Form — the booth first impression

The spectacle is already there. These remove the small frictions that quietly undercut it in the first two seconds, and make the payoff readable from across a room.

Warm up the cold-open

F1

First load sits at a red −265 MW. It is physically honest (sub-breakeven Startup, deliberately teaching that Q > 1 ≠ net power), but a passer-by reads red-negative as broken two seconds before they would ever see ignition.

Why it matters: the first beat decides whether someone stops. Keep the lesson; soften the open.

Hook: label the state "Warming up," seed a gentler near-breakeven default, or let the first load briefly auto-ramp to a net-positive moment.
Quick winEffort · LowHS / public

Promote the hero numbers

F2

Reactor state, Net electric, and Energy gain Q render at 0.92rem in a quiet strip — smaller than the in-panel metrics, and only nudged to ~1.04rem in kiosk. The single most important live results are the least prominent numbers on screen.

Why it matters: the wow moment is "a kid 8 ft away sees Q jump when they crank a slider." Make the trio the visual hero.

Hook: raise the badge values to clamp(1.1rem,1.6vw,1.6rem) and ~1.8rem in body.kiosk; tint the Q and net badges by state.
Quick winEffort · LowAll

Sharpen the hero plasma on retina tablets

F3

The WebGL core is sized in CSS px, then stretched across the DPR-scaled 2D canvas, so the 60-step raymarch runs at 1/4–1/9 the pixels and looks soft on exactly the iPads/Surfaces a booth uses — while the 2D coils beside it are crisp.

Why it matters: the volumetric plasma is the most photographed thing in the app; it should be the sharpest.

Hook: const s = Math.min(devicePixelRatio||1, 2); render at w*s × h*s, keep the drawImage target at w,h, lower the cap under liteMode.
High impactEffort · LowAll

Make the annunciator legible

F4

The six status lamps are 0.62rem (~10px) uppercase in --faint on near-black when off — they read as dead pixels until lit, losing the "control room" metaphor most of the time.

Why it matters: an annunciator wall is one of the strongest "this is real" cues; it has to be readable to land.

Hook: bump to ~0.7rem, raise off-state text to --muted, and add a leading LED dot so on/off reads by shape as well as color.
Quick winEffort · LowAll

Keep hotspot labels inside the stage

F5

The reactor hotspot labels sit on top of the plasma, and at the ~2-column breakpoint (stage column ≈520px — a common laptop/tablet width) the "Blanket" label clips off the right edge; on phones the "Magnetic Confinement Vessel" title runs under the "?" button.

Why it matters: clipped/overlapping labels are the small tells that separate "exhibit" from "student project."

Hook: clamp hotspot label positions to the stage with a small inset, nudge labels off the core, and give the stage title room to the right of the help button.
Quick winEffort · LowAll
05

Function — engagement & accessibility

The features exist; these make them found and usable by everyone, including the keyboard, screen-reader, and phone visitors a campus will expect you to serve.

Greet the first-time visitor

U1

Nothing prompts a newcomer facing a three-column control room, and the fusionTourDone first-run flag is written but never read — so the tour never auto-offers.

Why it matters: at a booth, median dwell is seconds; one zero-friction prompt is the difference between bouncing and entering the loop.

Hook: on load, if the flag is absent, show a single dismissible "New here? Take the 30-second tour / Just let me play" over the reactor.
Quick winEffort · LowAll

Fix the mobile scroll-trap

U2

The reactor canvas uses a passive:false touchmove with an unconditional preventDefault() and no touch-action. Since the reactor fills the first phone screen, a visitor who scans the QR and swipes to scroll just orbits the reactor and gets stuck.

Why it matters: the QR follow-up audience is mostly on phones — the exact people outreach wants to convert.

Hook: set touch-action, only preventDefault once a real drag threshold is crossed, or let near-vertical swipes pass through to the page.
High impactEffort · LowAll

Surface missions, and hint them

U3

The seven missions sit below both the sim grid and the Balance-of-Plant panel, carry no starting hint, and their completion toast is hidden in kiosk and far from the controls — so the strongest replay loop is undiscoverable and feels unwinnable.

Why it matters: missions feed the takeaway card's "missions completed" stat and are the best reason to keep playing.

Hook: add a "0 of 7 challenges" chip in the status strip that scrolls to the panel; give each puzzle an optional hint (start preset + the one knob to trade); flash the chip on completion.
High impactEffort · MedAll

Make the guided story point at the control

U4

Story steps name a slider ("set temperature to ~15 keV") but never highlight or scroll to it — the tour has spotlight targets, the story does not — so "guided" interaction degrades to a slideshow.

Why it matters: directing the eye to the left-panel control is what makes predict-observe actually happen.

Hook: add a sel target to each STORY step and reuse the tour's spotlight ring + scrollIntoView; pairs with the cold-baseline fix in T0·3.
High impactEffort · MedHS

Manage focus in the modals

A1

Tour, Story, and the Takeaway card don't move focus in, trap Tab, or restore it on close; only About handles Escape. The card is marked aria-modal="true" but implements none of that behavior.

Why it matters: these dialogs are the primary guided paths; for keyboard/SR visitors they are currently a dead end.

Hook: one shared openDialog(panel, firstFocus, onClose) helper: focus in, trap, restore, Escape-to-close.
High impactEffort · MedAll

Speak units; expose chart data

A2 · A3

Sliders announce raw unitless numbers ("5", not "5.2 T"); the six <meter> bars and the canvas charts expose names but no data to a screen reader; and the aria-live status strip re-announces continuously changing telemetry — a firehose that makes the page unusable with a reader.

Why it matters: units are the entire point of a physics simulator; a blind undergraduate needs to hear "7.0 T."

Hook: set each slider's aria-valuetext from the formatted <output> you already build; add aria-label to the meters; drop aria-live from the numeric badges and keep one hidden region that fires only on discrete state changes; (larger) a visually-hidden text summary per chart, updated on redraw.

High impactEffort · MedAll

One more, when you reach it

A4 — keyboard orbit of the 3D stage. The reactor is the centerpiece; on a focusable canvas, map arrow keys to cam.yaw/pitch and +/− to zoom — the same state the drag handlers already mutate — so a keyboard-only visitor can look around it too.

06

Raise the ceiling — optional depth

None of this is required to donate. It is where the curious undergraduate and the next maintainer are rewarded, and it absorbs the three leftover "ambitious" bets from the original roadmap.

Physics depth that closes loops you already hint at

D1

Within the reachable range, hotter is always better — the famous reactivity rollover is never felt. There is no bremsstrahlung loss, so the Lawson low-temperature branch is asserted but not explainable, and density is decoupled from T/B (no Greenwald limit; only the beta wall bites).

Why it matters: any one of these turns a "magic number" into a discussion prompt and deepens the UG lab.

Hook: add a Prad term to the power balance; let the effective rate roll over past its peak; evolve a density/Greenwald check alongside burnT.
AmbitiousEffort · MedUG

The leftover big bets

D2

From the original roadmap, three items remain genuinely unbuilt: a full Three.js render track behind a flag (keep the current engine as the offline default), a two-player race-to-ignition for events, and a WebXR booth mode.

Why it matters: each raises the ceiling; none is needed for the gift, and each adds real maintenance the host program then owns.

Hook: gate any new renderer behind an interchangeable drawReactor() / drawReactorGL() flag and vendor the dependency so booths with no network still run.
AmbitiousEffort · HighAll

Maintainability for rotating student volunteers

M1

The burn-through constants are duplicated verbatim across two functions, the 0.36s timestep is a magic literal in several call sites, and regime thresholds and semantic colors are repeated across the model, annunciator, coach, and canvas. There is no smoke test for a heavily-tuned model, and the README points reviewers at backups/.

Why it matters: a student is meant to inherit this; small extractions make a well-meaning future edit safe.

Hook: hoist shared physics constants and a TICK_S; centralize thresholds/colors; add a tiny ?selftest harness that runs calculateModel() across a grid and asserts the invariants; add a "For maintainers" README map. Keep the single-folder, zero-dependency portability intact.

AmbitiousEffort · MedUG / maintainer

Make it the host program's own

P1 · P2

"Tokamak Learning Lab" is hard-coded across the markup and inside canvas-draw code, and a "Purdue" reference is baked into shipped copy — yet About invites a host to add its name. There is also no facilitator guide, no curriculum metadata (grade band, time, standards), and no version/changelog.

Why it matters: adoption depends on a program putting its own name on the exhibit cheaply, and on a volunteer being able to staff it confidently.

Hook: a single const BRAND = { program, logoUrl, siteUrl } read by the topbar, About, and the card; neutralize the hard-coded program reference; add a half-page facilitator run-of-show, worksheet metadata, an APP_VERSION + CHANGELOG, and trim backups/ from the shipped bundle.

High impactEffort · MedAll
07

The quick-win batch

Low-effort, high-credibility items that can land in an afternoon. Several change the first impression or flip an accessibility check for the cost of a few lines.

  • Add a LICENSE file and a README "License" section (T0·1).
  • Add the global :focus-visible ring and restore the .tip-dot outline (T0·2).
  • Correct the instructor-key Cruise Q to a model-matched range (~15–20) (T0·3).
  • Reconcile the README "tour runs on first visit" claim — wire the flag or fix the line (T0·3 / U1).
  • Set each slider's aria-valuetext from its existing formatted output (A2).
  • Remove aria-live from the numeric badges; route discrete state changes through one hidden region (A3).
  • Suspend audioCtx on document.hidden; add a ~60fps frame cap; broaden the lite-mode blur removal (R1).
  • Promote the status-strip hero numbers via clamp() sizing + a kiosk bump (F2).
  • Add a leading LED dot and a brighter off-state to the annunciator lamps (F4).
  • Standardize "14.1 MeV" and one operating-window range across all copy; soften "no long-lived waste" / "no meltdown" to precise wording (C1).
  • Neutralize the hard-coded "Purdue" reference; add an APP_VERSION surfaced in About + manifest (P2).
08

Suggested order of attack

Blockers first, then the first-impression and accessibility work that makes the gift land, then the optional ceiling.

FirstUnblock the donation

T0·1 LICENSE, T0·2 focus ring, T0·3 truth slips. Cheap, and they flip the legal, accessibility, and curriculum gates from fail to pass.

NextWin the first 5 seconds

F1 warm-start, F2 hero numbers, U1 welcome prompt, F4 lamps, plus the A2/A3 a11y one-liners and R1 robustness batch. This is what converts booth dwell-time into engagement.

ThenUsable by everyone

U2 mobile scroll-trap, A1 modal focus, A4 keyboard orbit, F3 retina plasma, U3 missions chip + hints, U4 story spotlight, F5 label clamps.

PackageMake it adoptable

P1 BRAND config, P2 facilitator guide + curriculum metadata + version/changelog, trim backups/ from the shipped bundle, update the README materials list.

When you want depthRaise the ceiling

M1 maintainability + smoke test, then D1 physics depth, and finally the D2 leftover bets (Three.js track, two-player race, WebXR) as appetite allows.

Three things to protect

Portability — keep it openable from one folder with no network. Accessibility — keep the reduced-motion, contrast, and colorblind paths first-class as you add features. Performance — gate every new heavy addition behind the same idle/visibility/lite checks, so it stays smooth on the weakest machine in the room.

09

Pre-donation QA checklist

Independent of the work above, run this pass before handing it over — the difference between "works on my machine" and "works at the event."

  • Open index.html directly from the folder (file://) with no server, in current Chrome, Edge, Firefox, and Safari.
  • Run on a real mid-range tablet for at least an hour: watch for heat, throttling, and frame-rate decay.
  • Open it on a phone, scan-to-run style: confirm you can scroll the whole page past the reactor (U2).
  • Project it in a bright room and read the hero numbers and lamps from across the room (F2, F4).
  • Drive each preset and each mission to completion; confirm state labels, lamps, and coach text all agree — and re-verify the instructor key against the live values (T0·3).
  • Do a keyboard-only and a screen-reader pass (T0·2, A1–A4).
  • Toggle OS reduced-motion and confirm the stilled experience is still coherent.
  • Leave it idle for several minutes and confirm it returns to a friendly state.
  • Re-verify the real-machine figures (ITER/SPARC/EAST move) at donation time.
